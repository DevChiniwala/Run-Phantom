# Research and verification record

Run Phantom is a local debugger for captured agent runs, with evaluation and a separate shared-project service. This record connects the source audit to the implemented behavior and identifies what the verification does not establish. Research date: **15 September 2026**.

## Source scope

The audit covered **25 distinct external repositories** at full pinned commit IDs. It inspected **133 unique source files**: 91 implementation/schema files, 34 test files, and eight supporting configuration or call-chain files. Three inspected license files are excluded from that count. Every repository had at least two substantive implementation files and one relevant test inspected. Run Phantom itself is not included in the repository count.

Reading depth ranged from complete files to selected function and test bodies. These are bounded source inspections, not reviews of every repository file. The file count does not represent papers, RFCs, articles or benchmark runs. Upstream test assertions were read; upstream applications, SDK test suites and performance benchmarks were not executed. No competitor code was copied into Run Phantom.

The repository names below identify the audited sources. `langtrace-ai/langtrace-python-sdk` was corrected to the official `Scale3-Labs` repository. The requested Braintrust and Ragas repository names resolve to the canonical repositories shown here. ## Local debugging

Replay attempts now own their asynchronous work and accept only correlated completion evidence. Starting another replay, cancelling, resetting or leaving the view cannot allow an older attempt to replace the displayed result. A stream ending without authoritative replay completion is not treated as success. The implementation is in [use-replay.ts](app/src/hooks/use-replay.ts); coverage includes [replay isolation](app/tests-e2e/replay-isolation.spec.ts) and [real local replay acceptance](app/tests-e2e/replay-debugging.spec.ts).

[Captured-run comparison](src/run-comparison.ts) reports changes in inputs, outputs, status, model, provider and available usage with bounded acquisition and response sizes. It matches unique sibling semantics under matched parents and unique complete input evidence; repeated ambiguous calls remain explicit. Tied or missing timestamps do not become order-change claims through arbitrary span IDs. The [comparison UI](app/src/components/RunComparison.tsx) retains links to the original evidence and the two-pane inspection flow. See [comparison regressions](tests/run-comparison.test.ts) and [browser comparison tests](app/tests-e2e/run-comparison.spec.ts).

The streaming audit found that an exporter can end an `OK` span after partial consumption. [Output-completion checks](src/spans/completion.ts) therefore distinguish explicit streaming evidence from generic span completion and preserve unconfirmed output as inspectable evidence without certifying equality or a passing output check. [Stream-completion regressions](tests/span-completion.test.ts) cover unfinished and completed streams, conflicting markers, multiple captured choices and unavailable attributes. Missing usage alone is not an interruption signal.

[Trace export/import](src/trace-export.ts) preserves captured evidence and annotations through an explicit versioned format, including saved-cache cases. Its identity, collision and round-trip behavior is covered by [API tests](tests/trace-portability.test.ts) and [browser handoff tests](app/tests-e2e/trace-portability.spec.ts).

## Evaluation

The evaluation path keeps missing, redacted, lossy and incomplete evidence distinct from successful outcomes. [Deterministic rules](src/evaluations/rules.ts) include versioned, type-sensitive tool-argument checks; [snapshots](src/evaluations/snapshot.ts) preserve the evidence used for a decision. See [tool-argument regressions](tests/evaluation-tool-arguments.test.ts) and [browser rule acceptance](app/tests-e2e/evaluation-tool-arguments.spec.ts).

[Repeated-trial analysis](src/evaluations/trials.ts) reads explicitly selected frozen experiments. It requires compatible dataset/evaluator identities, rejects repeated grading of the same case/run as separate trial evidence, and retains pass/fail/inconclusive counts with their denominator and unresolved bounds. [JSON/JUnit reports](src/evaluations/report.ts) retain strict gates and frozen identity while excluding raw payloads. Coverage includes [trial invariants](tests/evaluation-trials.test.ts), [MCP evaluation contracts](tests/evaluation-mcp.test.ts), [report tests](tests/evaluation-report.test.ts), and [trial browser acceptance](app/tests-e2e/evaluation-trials.spec.ts).

These results describe the selected captures. They do not establish independent samples, deterministic provider behavior, statistical significance or a market ranking. Distinct trace IDs can still share sessions, caches or unrecorded configuration.

## Shared observability

The [team service](src/team/server.ts) separates browser sessions from ingestion-only project credentials. [Storage](src/team/store.ts) scopes runs, spans, notes and checks to authorized projects and rechecks authority for sensitive operations. [Ingestion](src/team/ingest.ts) applies fixed credential redaction and bounded decoding before persistence. [Shared checks](src/team/checks.ts) use bounded calculation slots and frozen deterministic evidence. Coverage includes [authentication](tests/team-auth-integration.test.ts), [project isolation](tests/team-integration.test.ts), [ingestion limits](tests/team-ingest-http.test.ts), [check invariants](tests/team-checks.test.ts), and [team browser acceptance](app/tests-e2e/team-workspace.spec.ts).

The [team operating guide](src/team/README.md) records the exact HTTP trace endpoint and SDK configuration limits. This service does not provide OTLP logs or gRPC ingestion. OpenLLMetry and LiteLLM can route message content through logs instead of trace attributes; successful trace delivery cannot recover that missing content. Current Langtrace initialization supports standard OTLP, but endpoint precedence and suffix rules must be configured explicitly. SDK-specific setup examples are source-derived unless an executed compatibility test is separately reported.

Team HTTP ingestion uses `/api/team/ingest/v1/traces`. The pinned OpenLLMetry [message writer](https://github.com/traceloop/openllmetry/blob/62e24c2ffde6c1ee04dc290e52d8d5dbda054cff/packages/opentelemetry-instrumentation-openai/opentelemetry/instrumentation/openai/shared/chat_wrappers.py#L554-L612) emits `gen_ai.output.messages`; its [instrumentor configuration](https://github.com/traceloop/openllmetry/blob/62e24c2ffde6c1ee04dc290e52d8d5dbda054cff/packages/opentelemetry-instrumentation-openai/opentelemetry/instrumentation/openai/__init__.py#L24-L52) enables attributes with `use_attributes=True`. Content capture and an HTTP exporter must also be configured.

The pinned Langtrace [initializer](https://github.com/Scale3-Labs/langtrace-python-sdk/blob/462a04b361f62314fb6d2d873cd866959152aa35/src/langtrace_python_sdk/langtrace.py#L117-L200) prioritizes environment endpoints over `api_host` and appends `/v1/traces` to a custom host. For its derived URL, the team host prefix is `http://127.0.0.1:5949/api/team/ingest`, with HTTP/protobuf selected explicitly. Alternatively, a standard HTTP OTLP exporter supplied through `custom_remote_exporter` can target the full endpoint and carry the project bearer key. The legacy proprietary exporter class is a separate transport.

## Verification and remaining limits

The integrated verification recorded for this revision is:

| Verification surface | Recorded result |
| --- | --- |
| Native test suite | **493 passed; 3,044 assertions.** |
| Live-provider cases | **7 skipped.** They do not count as verified provider behavior. |
| Browser acceptance against the source-served application | **85 passed.** |
| Browser acceptance against the compiled executable | **12 passed.** |

These results were collected on **macOS arm64**. Fresh Linux and Windows native execution, other operating-system/browser combinations, and cross-platform performance were not verified by this run. The local replay acceptance cases use a controlled local endpoint and do not substitute for the skipped live-provider cases. Upstream suites and comparative throughput, latency, cost or reliability benchmarks were not run.

Checkpoint restoration, recorded-response execution, distributed asynchronous evaluation, SSO/public sharing, online sampling and statistical leaderboards remain separate capabilities requiring explicit contracts and tests. Observed telemetry does not contain arbitrary filesystem, network or runtime checkpoint state. Cancelling observation or an HTTP request does not guarantee rollback or termination of remote side effects.

The source audit supports the concrete correctness and inspection improvements above. It does not establish that Run Phantom outperforms every audited project or implements every feature in those repositories.
